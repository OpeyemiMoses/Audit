AUDIT Architecture & Developer Integration

A comprehensive reference manual detailing the Model Context Protocol (MCP) server, REST API endpoints, risk scoring rubric, and autonomous guardrail integration.

1. System Architecture Overview

AUDIT acts as an air-gapped security and market intelligence layer positioned directly between autonomous trading agents and on-chain liquidity pools. Instead of allowing agents to blindly sign transactions, AUDIT conducts pre-flight security evaluation across:

  • Bytecode Analysis: Direct RPC calls decompiling deployed bytecode to detect unverified code, proxy implementation redirects, and privileged owner roles.
  • Security Database Scans: Integration with GoPlus Security for real-time honeypot detection, buy/sell tax verification, and blacklist logic.
  • Groq LPU AI Synthesis: Fast sub-800ms inference via openai/gpt-oss-120b providing human-readable analysis of architectural trade-offs and enforceable safety recommendations.
  • Binance Market Depth: Real-time order book spread, bid/ask depth imbalances, and perpetual futures funding regimes.

2. Model Context Protocol (MCP) Server

AUDIT implements the official Model Context Protocol (MCP) specification via dist/mcp-server.js using Stdio transport. Any MCP client (Binance Agent OS, Claude Desktop, Cursor, ElizaOS) can consume the following 9 native tools:

audit_token Audits token contracts for honeypots, taxes, liquidity, and holder distribution.
audit_contract Inspects contracts for proxy patterns, admin functions, and verified source code.
audit_transaction Simulates transaction calldata, asset flows, and flags unlimited approvals.
audit_wallet Profiles counterparty wallet history, age, mixer interaction, and bot probability.
evaluate_decision Synthesizes trade context through Groq AI to yield an ALLOW, WARN, or BLOCK verdict.
get_market_data Fetches real-time Binance 24hr tickers, order book spread, and funding rate regime.
analyze_unified Autonomous target classifier routing addresses to their specialized security analyzers.

Frequently Asked Questions & Support

Common questions regarding risk score calculation, network availability, false positives, and Binance Agent OS integration.

How is the Composite Risk Score (0-100) calculated?

The Composite Risk Index is a weighted score combining on-chain bytecode flags (unverified source: +15, proxy pattern: +10, selfdestruct: +25, privileged admin roles: up to +30), GoPlus security flags (honeypot, excessive taxes, transfer pausers), and liquidity depth. Scores 0-30 are ALLOW (Low Risk), 31-65 are WARN (Moderate Risk), and 66-100 are BLOCK (High Risk).

Why does GoPlus show 'Not available' for Permit2 or Uniswap contracts?

GoPlus is primarily an ERC-20 token scanner and does not index all infrastructure protocol contracts or bridge routers. AUDIT automatically recognizes protocol infrastructure, avoids generating false alarms, and analyzes the contract directly from verified bytecode and Etherscan source code.

How does Groq AI formulate its security feedback?

AUDIT connects directly to Groq's high-speed LPU inference engine (running openai/gpt-oss-120b) to evaluate the contract bytecode, ABI, and telemetry. It produces plain-English explanations answering: (1) Why the risk score was assigned, (2) Why the developers designed the contract with that architecture, and (3) Concrete security feedback for agents and human operators.

Can AUDIT run without an internet connection?

AUDIT caches all on-chain telemetry and Groq reasoning in-memory (and optionally in Redis). If an external API encounters a rate-limit or network timeout, AUDIT gracefully falls back to deterministic bytecode heuristic analysis so autonomous trading agents never experience hard crashes.
